# Практика. Урок 19: структурное логирование с slog

Пакет `logging` — основа observability капстоуна (CAPSTONE.md, неделя 10:
`internal/telemetry/log`):

- `NewLogger` — готовый JSON-логгер с уровнем;
- `WithRequestID` — request-scoped логгер;
- `RedactHandler` — обёртка `slog.Handler`, маскирующая секреты.

## Задание

Реализуйте `TODO` в `logging/logging.go`:

1. `WithRequestID` — вернуть `l.With("request_id", requestID)`.
2. `RedactHandler.Handle` — замена секретов в **сообщении** и в **значениях
   атрибутов**, включая **вложенные группы** (рекурсия по `slog.KindGroup`).
   Создавайте новую запись через `slog.NewRecord(...)` — не `r.Clone()`,
   иначе старые атрибуты останутся рядом с новыми и секреты утекут в сырой
   JSON (см. комментарий в коде).
3. `RedactHandler.WithAttrs` — те же замены для предварительно прикреплённых
   атрибутов; порядок и имена атрибутов не менять, только значения.

Требования:

- секрет заменяется целиком: значение `"abc-s3cr3t-xyz"` при секрете
  `"s3cr3t"` становится `"abc-[REDACTED]-xyz"` (не обрезать хвосты!);
- несекретные атрибуты и сообщения без секретов не меняются;
- группы: маскируются значения на любой глубине.

## Перенос в капстоун

1. Скопируйте `logging/logging.go` в `orders/internal/telemetry/log/`
   (пакет `log`), импорты `practice/...` не нужны — пакет самодостаточен.
2. В `cmd/orders/main.go` собирайте логгер так:
   `log.NewLogger(os.Stdout, slog.LevelInfo)`, оберните `RedactHandler` со
   списком секретов из конфига (токены, ключи, номера карт).
3. В middleware (неделя 5) используйте `WithRequestID`: кладите логгер с
   `request_id` в `context.Context` и доставайте во всех слоях — тогда по
   одному `request_id` в лог-агрегаторе собирается вся цепочка запроса.
4. Проверьте вручную: `go run ./cmd/orders` + пара запросов — в логах
   `request_id`, секреты замаскированы.
