# Практика. Урок 8: context — отмена и дедлайны

Пакет `worker`: обработка очереди заданий, где у каждого задания свой таймаут,
а отмена родительского контекста мгновенно останавливает всю обработку.

## Задание

Реализуйте `TODO` в `worker/worker.go` (лекция: разделы «Дедлайны и таймауты»,
«Правила работы с context»):

1. `WithJobTimeout` — контекст с дедлайном не позже `timeout`; если у
   родителя уже есть более ранний дедлайн — вернуть его без обёртки.
2. `Run` — последовательная обработка заданий с `select` на `ctx.Done()` и
   чтение из `jobs`; отмена контекста возвращает накопленные результаты;
   закрытый канал — штатное завершение; результат каждого задания (включая
   ошибку) попадает в слайс.
3. `runJob` — имитация работы через `time.NewTimer` + `select` (без горутин!):
   таймер сработал — успех, контекст прервал — вернуть `ctx.Err()`;
   `timer.Stop()` через `defer`.

Семантика (её проверяют тесты):

- задание, превысившее `JobTimeout`, **пропускается** (результат с
  `context.DeadlineExceeded`), Run продолжает обработку;
- отмена контекста останавливает Run быстро и возвращает частичные
  результаты;
- после выхода из Run не остаётся «хвостовых» горутин — работа по заданию
  должна быть прерываемой через контекст, а не брошенной спать в горутине.

## Перенос в капстоун

1. В `orders/internal/service` добавьте раннюю проверку контекста в каждый
   публичный метод: `if err := ctx.Err(); err != nil { return ..., err }` —
   сервис не должен работать с отменённым контекстом.
2. В `orders/internal/cache` (урок 7) протяните контекст: методы кэша
   принимают `ctx context.Context` первым аргументом и проверяют `ctx.Err()`.
3. В `cmd/orders/main.go` задайте таймаут на стартовую инициализацию
   (например, прогрев кэша) через `context.WithTimeout` — чтобы зависшая
   инициализация не блокировала запуск сервиса навсегда.
