# Практика. Урок 6: pipeline обработки заказов

Пакет `pipeline`: конвейер этапов, где первый этап распараллеливается
(fan-out на N воркеров), результаты собираются обратно (fan-in) **с
восстановлением исходного порядка**, остальные этапы идут последовательно.

## Задание

Реализуйте `TODO` в `pipeline/pipeline.go` (лекция: разделы «Pipeline»,
«Fan-out / fan-in», «Владелец канала»):

1. Без этапов — заказы проходят насквозь (с уважением к `ctx.Done()`).
2. Первый этап: N = `runtime.GOMAXPROCS(0)` воркеров, у каждого свои каналы
   `in`/`out`; распределитель раздаёт заказы воркерам **по кругу**
   (индекс `% N`); читатели вычитывают выходы воркеров в отдельные слайсы;
   после завершения всех — слияние по кругу (`collected[0][k]`,
   `collected[1][k]`, …) восстанавливает исходный порядок.
3. Отмена контекста или ошибка любого воркера немедленно останавливают
   раздачу: распределитель обязан `select`-ить на `ctx.Done()` и на сигнал
   ошибки, иначе он зависнет на отправке в канал вышедшего воркера.
4. Остальные этапы — последовательно: текущий результат складывается в
   буферизованный канал, этап запускается в горутине, его выход вычитывается.
5. Канал закрывает только владелец: для первого этапа — Run (после раздачи),
   для последующих — горутина, запускающая этап (`defer close(out)`).
6. При ошибке или отмене Run возвращает уже обработанные заказы и ошибку
   (при отмене контекста — `ctx.Err()`).

Контракт `Stage` (см. `pipeline.go`) — часть задания: этап обрабатывает
заказы 1:1, сохраняет порядок своего потока, не закрывает каналы, уважает
контекст. Запускайте с race detector:

```sh
go test -race ./...
```
